# Recent ManiGuard engineering and validation progress

## What reusable helpers, entry points, tests, and configuration contracts were added or changed?

### Takeaway

The range `1432288..07a7e8c` adds a complete guarded execution and evidence stack for the separate four-start continuation screen, plus restoration, review, plotting, and a prospective progress-fitness component. The diff contains 17 new helpers, seven new entry points, one modified checkpoint entry point, and 14 new test modules. Most of the much larger JSON volume is frozen configuration, recovery evidence, audits, and preservation metadata rather than new controller logic.

### Cited Findings

- The full range changes 177 files with 32,726 insertions and 312 deletions. It adds 17 helper modules, seven scripts, 14 test modules, 25 continuation JSON records plus its README, and 94 latent-evolution JSON records. The Python code is concentrated in 39 changed helper, script, and test files; the rest is mainly evidence, paper source, generated assets, and research notes. [Range comparison](https://github.com/Sachin2911/Safety-Dial/compare/1432288...07a7e8c)
- The execution path is now separated into reusable layers. `ContinuationStudy` performs compound native or closure selection, one-pass feature encoding, request admission before inference, returned-receipt and RNG-chain verification, finite counter enforcement, and separate physical outcome derivation. [Runtime helper](../../experiments/helpers/maniguard_continuation_runtime.py) The source preparer changes only the checked evaluator import and records a new runtime digest. [Source helper](../../experiments/helpers/maniguard_continuation_source.py)
- The coordinator contract is durable and fail-closed. `ScreenLedger` binds one canonical run to one protocol hash, charges reservations before file preparation or process creation, limits the screen to four unique starts with no replacements, and requires each two-worker wave to complete before the next. It also requires successful original60 design verification, complete physical restoration, preservation of all terminal attempts, and absence of live original processes. [Admission helper](../../experiments/helpers/maniguard_continuation_admission.py)
- Independent guardians now enforce a 600-second initialization limit, 2,700-second full-start limit, finite environment, encoder, query, and physics counters, process-group termination, parent-death behavior, and an inherited exclusive service lease. [Limits helper](../../experiments/helpers/maniguard_continuation_limits.py) [Guardian helper](../../experiments/helpers/maniguard_continuation_guardian.py)
- Job preparation freezes the closure controller, native evaluator configuration, Jar scene digest, worker and GPU identities, service-ledger baseline, exact source bytes, runtime limits, original clearance, and protocol digest before dispatch. The episode entry point rechecks those bindings, the charged reservation, physical cutoff, service lease, source snapshot, scene asset, and simulator device before starting the native evaluator. [Job helper](../../experiments/helpers/maniguard_continuation_jobs.py) [Episode entry point](../../experiments/scripts/maniguard_continuation_episode.py)
- The screen entry point adds a read-only `--check` mode, live own-instance and watchdog validation, two-wave dispatch, resume by observing exact guardian identities, captured service tails, independent episode reading, immutable cached-result comparison, and a stop after any invalid charged start. It never silently relaunches or replaces an attempt. [Screen entry point](../../experiments/scripts/maniguard_continuation_screen.py)
- Evidence validation reconstructs every query choice, admitted request, returned action chunk, RNG transition, proposal, clipped executed action, monitor observation, image hash, and accounting join. The full reader additionally binds the native result, native monitor log, source snapshot, evaluator bytes, controller, scene, guardian, technical budgets, and saved outcome. [Evidence replay](../../experiments/helpers/maniguard_continuation_evidence.py) [Full result reader](../../experiments/helpers/maniguard_continuation_results.py) The service helper preserves the original append-only ledger prefix and copies only the episode-specific byte tail for later offline verification. [Service helper](../../experiments/helpers/maniguard_continuation_service.py)
- Progress attribution is explicitly post hoc. It requires an already verified full episode, treats the switch-boundary observation as part of the closure prefix, distinguishes nonprivileged from privileged eligibility, removes eligibility after any whole-episode violation, and grants no dispatch or expansion authority. [Progress helper](../../experiments/helpers/maniguard_continuation_progress.py)
- Restoration support was added for both studies. The original60 tool requires the exact 13-source authority, separately restored model and dataset archives, exact saved receipts, causal physical revalidation, and native monitor joins. [Original restoration helper](../../experiments/helpers/maniguard_latent_restoration.py) [Original restoration entry point](../../experiments/scripts/maniguard_latent_restoration.py) The screen recovery tool independently restores both waves, retains each archive tree, and permits only `screen.json` and the named coordinator log to differ across waves. [Screen restoration helper](../../experiments/helpers/maniguard_continuation_restoration.py) [Screen recovery entry point](../../experiments/scripts/maniguard_continuation_recover.py)
- Analysis utilities now include a complete 16-episode paired descriptive review, saved-trace gripper command and finger-joint analysis, trace-bound plotting, and CLI wrappers that refuse overwrites. [Final review](../../experiments/helpers/maniguard_review_final.py) [Gripper review](../../experiments/helpers/maniguard_review_handoff_gripper.py) [Plot helper](../../experiments/helpers/maniguard_continuation_plot.py)
- `maniguard_latent_checkpoint.py` was hardened so an explicit manifest can include hash-bound nested analysis files while flat report files remain automatically included. It rejects path traversal, secret-like path components, changed bytes, symlinks, and unlisted directory sweeps. [Checkpoint script](../../experiments/scripts/maniguard_latent_checkpoint.py) [Checkpoint tests](../../experiments/tests/test_maniguard_checkpoint_analysis.py)
- The new progress objective is prospective CPU software, not part of the completed search. It scores complete fixed panels with `F=(4N+1)sum(U)+sum(S)`, zeroes secondary progress for any violating episode, and returns identical per-episode learning rewards under the same objective. [Progress-fitness helper](../../experiments/helpers/maniguard_progress_fitness.py) Its receipt says the current optimizer was not modified, dispatch is unauthorized, and the retrospective preferred factual panel changes in 2 of 5 cohorts without reconstructing a different search history. [Progress-fitness receipt](../../configs/maniguard/continuation/progress-fitness-prototype-20261020.json)
- The frozen configuration binds one exposed Jar case, seed 6101920, four modes, two two-worker waves, 2,000 controls and at most 250 policy requests per start, four total charged starts, no replacements, 34 critical source hashes, and finite wall, initialization, preservation, and accounting limits. [Frozen protocol](../../configs/maniguard/continuation/handoff-screen-frozen-v1.json) The continuation README explicitly states that this is a capability screen and not evidence of EA advantage, learned-filter performance, or fresh generalization. [Continuation README](../../configs/maniguard/continuation/README.md)

### Inferences

- The reusable engineering contribution is strongest in admission, source binding, accounting, recovery, and independent replay. It is a robust experimental harness around an existing handoff selector, not a newly demonstrated safe-completion controller. The handoff selector itself predates this range, while the new range supplies guarded execution and evidence validation. [Range comparison](https://github.com/Sachin2911/Safety-Dial/compare/1432288...07a7e8c) [Continuation README](../../configs/maniguard/continuation/README.md)
- The 119 added JSON files should not be read as 119 new implementations. They mainly preserve staged restoration receipts, dataset and model receipts, checking progress, accounting, independent reviews, physical proofs, and final catalogs. [Latent-evolution README](../../configs/maniguard/latent-evolution/README.md) [Final preservation catalog](../../configs/maniguard/latent-evolution/preservation-catalog-final-20261020.json)

### Gaps

- No reusable ordinary-learning baseline, trained ROSARL task policy, learned safety filter, or qualified world model was added to the active physical controller in this range. The paper describes those as undeployed or prospective. [Paper README](../../docs/research/reports/maniguard-phase3-part1-gecco/README.md)
- The frozen screen uses absolute `/workspace/Safety-Dial` paths and a specific instance, GPU mapping, ports, and service ledgers. The recovery path is portable, but live redispatch is intentionally host-specific and the completed deadline has elapsed. [Frozen protocol](../../configs/maniguard/continuation/handoff-screen-frozen-v1.json)

## What do the commit sequence and diffs show about implementation maturity?

### Takeaway

The sequence shows a rapid progression from isolated synthetic software to bounded orchestration, prospective freezing, independent review, full physical completion, restoration, paper integration, and final preservation. Experimental record keeping is mature, but the scientific result is negative and the prospective fitness improvement remains inactive.
