# ManiGuard recovery goal prompt

19 October 2026. Copy the prompt below into a session that can access this repository
and the instance you have authorized. This file supplies a future goal; writing it
does not arm a goal, rent/restart a machine or launch an experiment.

The detailed scope, alternative designs and repair limits are in
[phase3Recovery.md](../../../phase3Recovery.md). The default is the repaired execution
comparison, with bounded offline repairs for Parts 3/4. A full scene-acquisition study
is an alternative primary session and needs its own frozen prerequisite/budget record.

```text
/goal Implement and execute the ManiGuard recovery plan in phase3Recovery.md to obtain
a completed, reproducible physical comparison and a defensible contribution assessment.
Read AGENTS.md, phase3.md, phase3Recovery.md, phase3Part1.md through phase3Part4.md and
their completed reports. Preserve all original results, protocols and source snapshots.

Use the default execution route: repair cap geometry and calibrate an active feedback
trigger, then compare actual evolution, matched random search and episodic ordinary
learning over the same frozen controller family. Keep identity and a fixed reference.
Select finalists using declared confirmation data and evaluate them on whole tasks
kept separate from development. Preserve the final evaluation allocation. Also use
cached features and passive recordings for the bounded Part 3/4 repair queue; a weak
model must not prevent direct physical evolution.

Work through recoverable failures autonomously. Diagnose, make an evidence-based fix,
run the smallest relevant check, and resume from saved audited state. Do not end the
whole run after an exception, dormant trigger, failed forecast or false-alarm gate.
Use the plan's finite repair/model/data queues and fallback routes. Fix comparison
baselines as carefully as the proposed method. Count every attempt and preserve
partial evidence. Never replace a valid poor outcome or tune on final audit labels.

Before running, identify the currently authorized instance and its real provider start,
remaining allowance, environments and assets. Use one GPU and at most the remaining
eight-hour allocation, or any earlier binding deadline. Do not create another rental,
restart a stopped rental or extend spending without existing explicit authorization.
Prepare on CPU before rental where possible. Install an independently supervised
deadline and verify crash/resume behaviour before expensive work. Select the full or
compact comparison from end-to-end timing alone, with time for repairs and preservation.
Do not reuse old instance IDs, absolute deadlines or completed-study coordinators.

Do not stop the instance prematurely because one worker or scientific candidate fails.
Worker failure returns control to the recovery loop; no shutdown-on-error trap or
finally handler may stop the provider. Early provider shutdown requires the complete
selected comparison and verified preservation, or my explicit instruction. At the hard
allocation deadline, stop the instance retaining its disk even if the goal is unmet,
and verify actual provider state independently. Keep backups incremental throughout.

Prioritize the cheapest next action that resolves a concrete uncertainty. Reuse pinned
assets and cached features, use one persistent policy server and one simulator worker,
avoid unchanged retries and unnecessary repeat tests, and respect all attempt/model
caps. Preserve native horizons, physical safety specifications, causal observations
and whole-task partitions. A changed scientific recipe needs a new prospective freeze.

Deliver working new recovery code and targeted checks; frozen configs and source hashes;
controller/model exports; search lineage and ordinary-learning logs; fresh per-task
safe completion, violations and unfinished counts for every condition; complete
simulator/query/time accounting; matched videos and figures; a concise research report;
and verified private backups with revision pins. Keep raw data, weights and secrets
out of Git. Explain which measured contrast supports each contribution claim.

Do not mark this goal complete for a plan, green tests, a saved model or a feasibility
diagnostic alone. Seek a useful measured improvement, but retain null/adverse outcomes
and do not extend sampling to manufacture a win. If the budget or a genuine external
blocker prevents the comparison, preserve the partial result, state that the objective
is unmet and give the exact next repair and cost. Continue independent useful work
while any necessary clarification is pending.
```

The goal's completion criteria, verification requirements, constraints and iteration
policy follow the [official OpenAI Goals guidance](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex).
The GPU deadline belongs to the experiment supervisor. A persistent agent goal does
not itself enforce a provider billing limit or guarantee a favourable scientific result.
